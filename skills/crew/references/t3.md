# crew on T3 Code

T3 can run a subagent on another provider, so seats with `provider`/`model` usually work here.

## Resolve the seats (once per session)

1. Call `orchestrator_capabilities` once. For each seat with a `model`, call it again with
   `search: "<model>"` if the model is not in the short list.
2. A model can be served by several runtimes. For example, `gpt-6-astra` may come through Pi
   (`github-copilot/gpt-6-astra`) while the Codex runtime is unauthenticated. Pick any runtime
   with `canRunChildTask: true` whose catalog has the model, and prefer the one named after the
   vendor when it works.
3. A runtime with a constraint ("not authenticated", "disabled") cannot fill the seat. Go to the
   next seat and log the reason with the constraint text.
4. Write the result in the epic Log, one line per role:
   `seat: <role> -> <runtime>/<model> (<effort>)`.

## Dispatch

- Same provider as the session: use the session's native subagent tool (`Agent` with
  `run_in_background: false` in a Claude session, `spawn_agent` then wait in a Codex session),
  with the tier mapped to that provider's models (see `claude-code.md` or `codex.md`). If the
  session has no native subagent tool, use `delegate_task` for every seat.
- Another provider, or settings the native tool cannot set: `delegate_task`, with the runtime and
  model from the resolved seat in its target. Put the effort under `target.options` with the option
  id the catalog lists (`effort`, `thinking` or `variant`).
- Follow a running delegate's `next`. Do not poll it. When you need its result before continuing,
  wait for its completion notification.
- Explorer, critic and reviewer write only their own output file; say so in the dispatch. The implementer
  works in the same checkout, never a separate worktree, so the review package matches.

## Record what ran

The delegate result names the runtime and model. Copy it into the Log line for that dispatch. If it
differs from the seat, that is a fallback: log it.
